#MULTISATGING 

The purpose of this multisatge is to reduce the size of the image

Without multistage 

we build a docker file 

FROM base osworkdir

copy
run 

CMD
this as like 800 mb if we buid the IMAGE


Now with multi stage concept 
Docker file will be like

FROM ubuntu:latest AS build # keeping alias name form thsi ubuntu 

WORKDIR /app

COPY main.go /app

RUN apt-get update && apt-get install -y golang-go

ENV GO111MODULE=off

RUN CGO_ENABLED=0 go build -o /app1 . #upto this it is a build stage

FROM scratch # here the next stage that is final stage is staring 

COPY --from=build /app1 /app1 # This will get the whole build stage as binary and get the content from the src stg to the this des stg 

ENTRYPOINT ["/app1"] # run the go lang

DISTROLESS IMAGES:

A distroless image contains an application runtime and the necessary supporting files, without a conventional operating-system user space full of shells, package managers and general-purpose utilities.

For example, a Java distroless image can provide a Java runtime without including a shell or package manager.


A distroless image is not necessarily empty. Unlike scratch, it can contain runtime libraries, CA certificates and other supporting files.

It has only runtime no OS package will be there so the size is less

Advantages:

as it has only runtime of prog language security is high as there no OS package so OS threat vulnerabilty is low

and reduce the size tool

WORKDIR /app

COPY main.go /app

RUN apt-get update && apt-get install -y golang-go

ENV GO111MODULE=off

RUN CGO_ENABLED=0 go build -o /app1 .

FROM scratch

COPY --from=build /app1 /app

ENTRYPOINT ["/app"]
